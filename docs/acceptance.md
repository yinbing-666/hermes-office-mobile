# 验收清单

默认验收不执行 POST。每个用例都按“入口、操作、预期结果、失败时应保留的证据”记录。

## A-01 生产首页与静态资源

- **入口**：`https://office.example.com/`
- **操作**：打开首页并硬刷新；检查 HTML 引用的 JS/CSS、manifest、favicon 和 Service Worker 请求。
- **预期结果**：页面正常加载；资源均为 200；公网 HTML 资源哈希与服务器 `frontend/dist/index.html` 一致；控制台无未处理错误。
- **失败时应保留的证据**：时间、URL、原始截图、控制台错误、失败请求、响应状态与服务器构建哈希。

## A-02 移动端布局

- **入口**：公网首页及员工、任务、选题、空间、工作流页面。
- **操作**：使用 390×844 视口逐页打开，展开长任务标题与详情，检查底部导航和页面根节点宽度。
- **预期结果**：`document.documentElement.scrollWidth` 不大于视口宽度；无页面级横向滚动；导航、长文本和按钮保持可见、可触达。
- **失败时应保留的证据**：页面、视口尺寸、横向溢出元素的边界数据、原始截图和控制台日志。

## A-03 BFF 健康状态

- **入口**：`GET http://127.0.0.1:8787/api/health` 与 `GET https://office.example.com/api/health`
- **操作**：分别执行本机和公网 GET，并只读检查 `systemctl --user is-active hermes-office-mobile-bff.service`。
- **预期结果**：服务为 `active`；两处接口均返回 200；响应不包含 key、token 或凭证值。
- **失败时应保留的证据**：时间、状态码、脱敏响应、服务状态和最近日志；不得复制敏感配置内容。

## A-04 只读数据页

- **入口**：员工、任务、进化、选题和活动页面；对应 GET 接口。
- **操作**：刷新页面并核对员工状态、任务分类、空态和最近更新时间。
- **预期结果**：真实数据正常展示；无数据时显示明确空态；离线时不伪造在线、送达或完成状态。
- **失败时应保留的证据**：页面截图、失败 GET、状态码、脱敏响应和控制台错误。

## A-05 Outbox 安全状态

- **入口**：任务页补投区域与 `GET /api/outbox`。
- **操作**：只读查看队列数量、旧消息提示和自动补投开关；不点击手动补投，不执行 retry POST。
- **预期结果**：自动补投默认关闭；超过 48 小时的旧消息有明确提示并默认跳过；页面不把待补投显示为已送达。
- **失败时应保留的证据**：队列统计、时间范围、页面截图、GET 响应和前端状态；消息正文按敏感信息处理。

## A-06 工作流模拟态

- **入口**：工作流页面。
- **操作**：检查页面模式标识、节点编辑、草稿保存和清空确认；不得调用真实执行 POST 作为默认验收。
- **预期结果**：模拟模式始终可见；模拟完成不显示为已调用 Hermes 或真实交付；清空草稿前出现确认。
- **失败时应保留的证据**：工作流 ID、模式字段、页面截图、控制台日志和相关 GET 响应。

## A-07 消息、补投与 Kanban 写操作

- **入口**：`POST /api/messages`、`POST /api/outbox/retry`、`POST /api/kanban/unblock/{task_id}`。
- **操作**：默认跳过。只有管理员明确指定目标、内容和影响后，才按单次授权执行一个最小请求。
- **预期结果**：未获确认时不产生请求；获确认后仅影响指定目标，并以服务响应和页面／任务状态证据判断结果，不能用前端点击或本地入队代替成功。
- **失败时应保留的证据**：授权范围、时间、脱敏请求摘要、原始服务响应、任务 ID、页面状态和失败日志。

## A-08 公网安全边界

- **入口**：`https://office.example.com/api/*`
- **操作**：审阅本地认证模式、服务端会话、角色授权、限流和 CORS 的当前事实；不进行攻击性测试或未授权业务写请求。
- **预期结果**：源代码已实现但未启用时，文档和 ROADMAP 必须继续标记公网风险；任何人都不把 CORS 或“代码已写完”描述为线上鉴权已经生效。
- **失败时应保留的证据**：相关配置位置、脱敏响应头、运行模式、风险说明和复现步骤，不记录 JWT、Cookie 或配置值。

## A-09 本地登录与 BFF 拒绝路径

- **入口**：应用登录页、`GET /api/session` 与 BFF 安全测试。
- **操作**：先运行 `test_access_security.py test_local_security.py`；上线后验证未登录只显示登录页、错误密码统一拒绝、频繁失败被限流、正确密码建立 admin 会话、退出后会话失效，并确认无会话请求、错误 Origin 和重复幂等键不会执行第二次业务函数。除登录和退出外不得执行成功 POST。
- **预期结果**：拒绝状态分别符合 401／403／409／429 契约；有效会话的 GET 正常；错误响应和审计不包含密码、原始会话 token、Cookie、消息正文或 API key。
- **失败时应保留的证据**：时间、脱敏身份、状态码、request ID、测试名称、服务日志和浏览器网络记录；不得保存密码或完整 Cookie。

## A-10 构建检查

- **入口**：服务器项目目录。
- **操作**：运行 `git diff --check`，然后在 `frontend/` 运行 `make gate`。
- **预期结果**：两项均通过，且验证过程中没有调用 POST、没有修改服务或生产配置。
- **失败时应保留的证据**：完整命令、退出码、首个有效错误、相关文件和当前 `git status --short`。
